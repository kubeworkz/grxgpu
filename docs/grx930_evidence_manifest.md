## 1. Status definitions

- **Workspace verified:** directly inspected in this worktree (file, path, current repository metadata, or command availability only).
- **Historical artifact:** a saved log or report records a result, but the run was not reproduced and its inputs are not cryptographically tied to the current source snapshot.
- **Reproduced:** the exact command was run successfully against the identified source and its output checked during this audit.
- **Blocked:** reproduction is not possible from the current copy because required source, tools, hardware, or inputs are absent.
- **Unverified:** mentioned in a plan/report or implied by an artifact, without primary evidence establishing the claim.
- **Not assessed:** would require restricted credentials/PDK contents, owner attestations, or physical hardware access not performed here.

Presence is not operational proof. A source file is not a build; an OOC FPGA report is not a full-SoC timing result; a bitstream is not a programmed-board measurement; and a PDK-named directory is not proof of licensing or signoff readiness.

## 10. Evidence requested to close E-002

1. **Authoritative source:** repository/branch/commit or archive checksum; submodules; complete CPU/NPU RTL; benches; generated inputs; and reviewed source inventory.
2. **Reproducible simulation:** exact tool versions, commands, test vectors/golden outputs, firmware hashes, complete logs, and passing single- and multi-core results; investigate the saved suite timeout.
3. **FPGA:** complete project/constraints, current timing summary with clock coverage, utilization and DRC, bitstream hash, board/device/revision, programming transcript, workload logs, and physical clock/power/thermal measurements.
4. **ASIC/PDK/IP (restricted):** verified foundry/node/revision and commercial rights; compatible libraries/corners, SRAM, IO/ESD, DDR, DFT, signoff decks/tools, package and manufacturing route. Record a safe reference and owner here, not restricted content.
5. **Review:** named RTL/verification, FPGA/board, physical-design, and legal/sourcing reviewers to attest to the relevant entries.

E-002 closes only after a named reviewer reconciles this manifest with the authoritative artifacts and the baseline is reproducible or explicitly classified unavailable/unsupported. E-002 closure does not pass PDK-rights, simulation, FPGA-validation, or tapeout gates by implication.
